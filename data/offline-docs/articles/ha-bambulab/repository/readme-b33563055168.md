# Bambu Lab

A Home Assistant Integration for Bambu Lab printers.

> [!NOTE]
> **This is a fork.** It tracks [greghesp/ha-bambulab](https://github.com/greghesp/ha-bambulab)
> and adds one capability: **another program on your network can hand printers to Home Assistant**,
> instead of a human retyping every serial, host and access code into the UI.
>
> Home Assistant does not expose config-entry creation over the REST API — only over the
> authenticated WebSocket API — so a plain HTTP call cannot add a printer. There are two ways
> around that, and this fork implements **both**:
>
> | | **A. Discovery — no token** | **B. Service call — token** |
> | --- | --- | --- |
> | Who starts it | Home Assistant, after the slicer advertises `_bambu-slicer._tcp.local.` | The slicer |
> | HA credential | **None at all** | A long-lived access token |
> | Authorisation | The user confirms the discovery card in the HA UI | Whoever holds the token |
> | Good for | Setting up your own machine | Scripts, automations, unattended runs |
>
> ```
> A:  slicer advertises  ->  discovery card  ->  user confirms  ->  import step  ->  entries
> B:  POST /api/services/bambu_lab/add_printer               ->  import step  ->  entry
> ```
>
> Both end at the same import step, so a printer added either way is identical to a hand-added one.
> Neither skips verification, neither creates duplicates, neither does cloud mode, and neither logs
> the access code. Full detail — including what the slicer must implement — is in
> [docs/unattended-printer-add.md](app-doc://article/ha-bambulab.repository.86d6514a29f5e675); what was actually tested is in
> [docs/verification.md](app-doc://article/ha-bambulab.repository.90d52690bcd71f46).
>
