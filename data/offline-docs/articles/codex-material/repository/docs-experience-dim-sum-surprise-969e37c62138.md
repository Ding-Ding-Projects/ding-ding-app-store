# The dim sum surprise

> Once in a hundred launches, Codex Studio says hello with a dish of dim sum instead of nothing.
> It is a small delight, not a feature anyone has to manage: it never blocks startup, never steals
> focus, never fires twice in a launch, and there is one switch that turns it off forever.

**Implementation:** `app/cx-dimsum.js` (`window.CX_DIMSUM`, the generated dish catalog) behind the
launch gate `CX.dimsum` in `app/codex-core.js`; the card and its bindings in `app/index.html`
(`dimSumVals`). Pictures are bundled PNGs in `app/dimsum/`, produced by `tools/sync-dimsum.ps1`.

## Behaviour

At startup, after the tab strip and the notification centre are wired, the app takes exactly one
draw. On a hit it shows a small card naming the dish in both languages beside its picture. The card
auto-dismisses after **9000 ms**, and carries a close control so it can be dropped sooner.

It is a corner card, not a dialog. It does not gate startup, does not take focus, and the app is
fully usable the moment it appears — consistent with the project's rule that anything which only
informs is a non-blocking surface.

The dish name is a **fact and never changes with the funny level**. `Shrimp dumpling · 蝦餃` reads
identically at funny level 1 and at level 5; only the greeting copy around it changes voice.

## The 1% rate, and how it is drawn

Two gates sit in series. `CX.dimsum.draw()` in `app/codex-core.js` decides *whether to draw at all*,
and `CX_DIMSUM.draw(rate, rng)` in the catalog performs the draw.

| Order | Check | Effect |
| --- | --- | --- |
| 1 | `drawn` flag | Already drawn this launch → `null`. **One draw per process, ever.** |
| 2 | `settings.get("dimSum", true)` | Turned off → `null`, no random number consumed |
| 3 | `store.get("hasLaunchedBefore")` | First run → records the launch, returns `null` |
| 4 | `CX_DIMSUM.draw(0.01)` | A fresh random number decides; ~1 launch in 100 returns a dish |

The rate is a ceiling, not a target. The draw is fresh per launch — nothing is carried over, no
"due" counter accumulates, and a run of unlucky launches does not make the next one likelier. The
`drawn` flag is what guarantees it cannot fire twice in one launch even if a caller asks again.

The settings **Preview** button calls `draw(1)` deliberately, so a user can see the surface without
waiting on chance. That is the only place a rate other than `0.01` is passed.

## The off switch

Settings → the **Show the dim sum surprise** toggle, persisted under the `dimSum` key, default
**on**. It is honoured absolutely and checked *before* the random draw, so switching it off costs
nothing and leaks nothing. Because the toggle is an ordinary setting it participates in the app's
local version history like any other record, so turning it off is itself undoable.

## Accessibility

**Alt text.** Every dish carries `alt.en` and `alt.yue`, and both name the dish, so a screen-reader
user gets the same delight rather than "image". `dimSumVals` picks the string matching the active
language mode and sets it as both `alt` and `title`.

**Motion.** The card should honour the app's `reducedMotion` setting (`app/codex-core.js`). See
*Known issues* — it does not currently consult it.

**Quiet hours.** A do-not-disturb or quiet-hours preference must suppress the surprise entirely.
See *Known issues* — no such setting exists in the app yet, so there is nothing to honour and
nothing that suppresses the card outside working hours.

**Sound.** The surprise is silent. It never routes through the TTS narrator: the narrator is
reserved for app events, and a delight that talks over a screen reader is not a delight.

## Where it deliberately never appears

| Situation | Why |
| --- | --- |
| **First run** | A brand-new user is being introduced to the app. A random food card in that first minute reads as a bug, not charm — so the first launch only records that it happened. |
| **An error path** | Someone reading a failure is mid-problem. Decorating that moment is the single worst time to be playful. |
| **An update** | The user is waiting on a version change and watching for what broke. |
| **Mid-task** | The card is startup-only by construction; it is never raised in response to user work. |

The first-run rule is enforced in code by the `hasLaunchedBefore` gate. The error-path and update
rules are currently **structural rather than enforced** — see below.

## Adding a dish

Dishes are **not hand-edited**. `app/cx-dimsum.js` is generated and carries a
`GENERATED by tools/sync-dimsum.ps1 — do not edit by hand` header; anything typed into it is lost on
the next sync.

The source of truth is the shared Hong Kong dim sum catalog (`dim-sum/index.json` in the
instructions repository), which holds native-resolution lossless PNGs. To add a dish:

1. Add the record and its image to that catalog, with `name.en`, `name.zhHant`, `jyutping`, and
   `image.alt.en` / `image.alt.yue`.
2. Re-run the sync from the repository root:

   ```powershell
   pwsh -File tools/sync-dimsum.ps1 [-CatalogRoot <path>] [-Count 20] [-Size 256]
   ```

3. Commit the regenerated `app/cx-dimsum.js`, the new `app/dimsum/*.png`, and
   `app/dimsum/manifest.json`.

The sync downsamples each photo to 256×256 — crisp at 200% display scale, where the card draws it at
56 CSS pixels — because twenty 2.3 MB originals do not belong inside a desktop installer. It skips
any record whose PNG is missing (a broken picture is worse than a shorter menu) and spreads its
selection across the catalog so the surprise is not twenty variations of the same dumpling.

**Names must be correct.** The dish name is the one thing in this feature that is never styled,
softened, or improvised. `alt.yue` must be natural written Hong Kong Cantonese — not 書面語, and not
a machine-spliced mixture of the two languages.

## Security and privacy

Images are **bundled local assets**. Nothing is fetched at runtime: no CDN, no third-party host, no
tracking pixel, no analytics ping. The committed output means a build never needs the (private)
catalog repository either. The feature reads one setting and one launch flag, and writes only the
launch flag.

## Known issues

Recorded because they are real and reproducible, not predicted.

| # | Issue | Evidence |
| --- | --- | --- |
| 1 | ~~**The picture is broken.**~~ **Fixed.** The binding reads `dish.image` — the PNG path the generated catalog actually provides — rather than a `dish.art` property that never existed. | Was: `data:image/svg+xml;charset=utf-8,undefined` on every dish |
| 2 | ~~**The greeting renders as a raw key.**~~ **Fixed.** `dimsum.greeting` is defined in `cx-i18n.js`, in both languages at five levels, and interpolates the dish name. | Was: the literal text `dimsum.greeting` in every language mode |
| 3 | **`draw(NaN)` fires on every launch.** `typeof NaN === "number"`, so the rate guard keeps `NaN`, and `random() >= NaN` is always false. Measured rate: **1.0000**. A caller handing in a corrupted persisted value turns a 1% delight into a card on every single launch, violating "never more frequent than the stated rate". | `CX_DIMSUM.draw(NaN)` over 200 000 iterations |
| 4 | **Four Cantonese alt strings contain untranslated English.** e.g. `一份擺喺a stainless-steel Hong Kong street-food counter嘅豉油滷水墨魚。` A Cantonese screen-reader user hears an English scene fragment mid-sentence. The generator copies `image.alt.yue` verbatim, so the defect is in the upstream catalog. | `hk-dish-0503`, `0506`, `0509`, `0512` |
| 5 | **The catalog is not all dim sum.** It currently includes 燒鵝 (roast goose), 乳豬拼盤 (suckling pig platter) and 咖喱魷魚 (curry squid) — 燒味 and street food, not dim sum — for a feature specified as showing *a dim sum dish*. `CATALOG_STATUS` is `"in-progress"`. | 72 bundled records |
| 6 | **No error-path or update guard exists.** `app/index.html:1021` comments "never during an error path", but `CX.dimsum.draw()` only checks the once-per-launch, off-switch and first-run conditions. Today the card cannot collide with an error because it is raised once at startup and never again — the protection is structural, not enforced. Any future call site would need the guard written. | `codex-core.js:538-548` |
| 7 | **`reducedMotion` and quiet hours are not consulted.** `reducedMotion` exists as a setting but the dim sum card does not read it; there is no quiet-hours setting at all. | `codex-core.js:521` |

Issues 1 and 2 were user-visible on every appearance and are both fixed. The remaining five are
real but quieter: three are upstream-catalog or specification issues, and two are protections that
hold structurally today rather than being enforced in code.
